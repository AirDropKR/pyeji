# 공유 미리보기 이미지(og:image) 자동 생성 제안 (작업 9)

1200×630 PNG를 빌드할 때 페이지마다 만든다. 새 의존성이 필요해서 확인 후 구현한다.

## 방법 비교

| | A. satori + sharp (권장) | B. @vercel/og | C. 직접 그린 SVG + sharp |
|---|---|---|---|
| 새 의존성 | satori 1개 (sharp는 Astro에 이미 있음) | @vercel/og (satori·resvg wasm 포함, 큼) | 없음, 단 글자를 경로로 바꾸는 opentype.js 필요 |
| 방식 | HTML/CSS 비슷한 구조를 SVG로 바꾸고(글자는 폰트에서 경로로 변환) sharp로 PNG | A와 같지만 Edge 런타임용 | SVG를 손으로 조립 |
| 한글 폰트 | 폰트 파일을 넘기면 됨 | 같음 | 글자마다 경로 변환 코드를 직접 |
| 유지보수 | 레이아웃 고치기 쉬움 | 쉬움 | 어려움 |
| 빌드 시간 | 페이지 50개 기준 수 초 | 비슷 | 비슷 |

권장: A. 의존성이 하나만 늘고, Cloudflare 빌드(Node)에서 그대로 돈다.

## 한글 폰트
- satori는 woff2를 못 읽어서 TTF/OTF가 필요하다
- 방법 1 (권장): Black Han Sans, IBM Plex Sans KR(Regular·Bold) TTF를 저장소에 넣는다 (OFL 라이선스, 합계 약 3~4MB). 빌드에 네트워크가 필요 없다
- 방법 2: 빌드할 때 구글 폰트 `css2?family=...&text=필요한글자`로 쓰는 글자만 받은 부분 폰트를 쓴다. 용량은 작지만 빌드가 네트워크에 의존한다. 실패하면 이미지 없이 빌드를 계속하도록 처리 필요
- 이미지에 들어가는 글자는 시즌 이름·날짜·게임 이름·글 제목뿐이라, 방법 1에서도 빌드 때 필요한 글자만 추려(subset) 메모리를 줄일 수 있다

## 레이아웃 (1200×630)
- 배경: 종이색(#e8e4da) + 크라프트지 테두리(#c9af86, 24px)
- 왼쪽 약 40%: 주섬이 2D 전신 (`mascotFor(gameId, 'full')`, 없으면 게임 도장)
- 오른쪽: 게임 약칭(작게) → 시즌 이름(크게) → 날짜 "11월 14일(토) 오픈"(가장 크게) → D-day 도장(보조) → 맨 아래 "폐지.com"
- 안전 영역: 핵심(시즌 이름·날짜·도장)은 가운데 1000×500 안에. 카카오톡이 2:1이나 더 좁게 잘라도 남게

## 페이지별 내용
- 시즌 상세: 위 레이아웃
- 게시글: 글 제목 + 연결된 시즌 날짜. 공식 대표 이미지(cover)가 있는 글은 지금처럼 그 이미지를 쓸지, 생성 이미지를 쓸지 선택 필요
- 게임 페이지: 게임 이름 + 다음 시즌 날짜 (미발표면 현재 시즌)
- 메인·기타: 고정 이미지 1장 (주섬이 + "핵앤슬래시 시즌 일정, 한국 시간으로")

## D-day가 굳는 문제
- 카카오톡·디스코드는 처음 받은 이미지를 오래 저장한다. 그래서 날짜를 주인공으로, D-day는 보조로
- 매일 오전 7시 자동 재빌드 때 다시 만들고, 파일 이름에 날짜를 붙인다: `/og/games-poe1-seasons-3-30-20261020.png`
- 새로 공유하는 링크는 새 파일 이름을 받으므로 최신 이미지를 받는다

## 구현 위치 (확정되면)
- `src/pages/og/[...slug].png.ts` (정적 엔드포인트, getStaticPaths로 페이지 목록 생성)
- `src/lib/og.ts` (레이아웃), `src/assets/fonts/` (TTF)
- Base.astro의 `image` 기본값을 생성 이미지 주소로

## 확인 방법
- 카카오 공유 디버거: https://developers.kakao.com/tool/debugger/sharing (캐시 초기화 버튼 포함)
- 디스코드: 개인 채널에 링크를 붙여 미리보기 확인 (캐시가 길어서 주소 끝에 `?v=날짜`를 붙여 시험)
- 페이스북 공유 디버거: https://developers.facebook.com/tools/debug/

## 운영자가 정할 것
1. 방법 A(satori 추가)로 진행해도 되는지
2. 폰트 방법 1(저장소에 TTF, 약 3~4MB)인지 2(빌드 때 내려받기)인지
3. 공식 이미지(GGG·블리자드)를 배경으로 쓸지 (시안을 보고 결정)
4. 주섬이 2D 전신 이미지 (작업 8)

# 구현 결과 (2026-10-21)

- 방법 A로 구현: satori + sharp(Astro에 이미 있던 0.35.5를 package.json에 명시). 새로 늘어난 라이브러리는 satori 하나
- 폰트: `src/assets/fonts/`에 서브셋 TTF 3개(Black Han Sans, IBM Plex Sans KR Regular·Bold, 합계 약 2.4MB)와 OFL 라이선스, 글자 목록 `charset.txt`(2,499자: 한글 2,350 + 영문·숫자·기호)
  - 다시 만들기: `pip install fonttools` 후 `python scripts/subset-fonts.py` (원본은 .cache/fonts/에 자동으로 받음, 저장소에 넣지 않음)
  - 서브셋에 없는 글자가 이미지에 들어가면 빌드 로그에 `[og] ... 폰트 서브셋에 없는 글자` 경고. 기호라면 스크립트의 SYMBOLS에 추가하고 다시 실행
- 생성: `src/pages/og/[name].png.ts` (내용) + `src/lib/og.ts` (레이아웃) + `src/lib/og-paths.ts` (주소). 기본 1 + 게임 6 + 시즌 26 + 글 12 = 45장, 합계 약 3.3MB
- 파일 이름: `/og/{종류}-{id}-{YYYYMMDD}.png` (빌드한 날의 한국 날짜). 매일 오전 7시 재빌드 때 새 날짜로 다시 만들어지고, 지난 날짜 파일은 빌드 결과에 없음
- 빌드 시간: 약 1.1초 → 약 7.7초 (이미지 45장 생성 약 6.5초)
- 구조화 데이터(Article·Event)의 image는 공식 대표 이미지가 있으면 그것, 없으면 생성 이미지

## 공유 화면 확인 방법

카카오톡
1. https://developers.kakao.com/tool/debugger/sharing 에 카카오 계정으로 로그인 (개발자 등록이 필요하면 무료로 등록)
2. 주소 입력 (예: https://pyeji.kr/games/poe1/seasons/3-30/) → 미리보기 확인
3. 이미 한 번 공유된 주소는 카카오가 오래 저장한다. 화면의 "캐시 초기화"를 누르거나, 다음 날 자동 재빌드로 이미지 이름이 바뀐 뒤 다시 확인

디스코드
1. 나만 있는 서버나 DM에 주소를 붙여넣어 미리보기 확인
2. 디스코드도 미리보기를 오래 저장한다. 같은 주소를 다시 시험할 때는 끝에 `?v=날짜`를 붙여 새 주소로 인식시킨다 (예: https://pyeji.kr/?v=1021)

공통
- 이미지 파일을 직접 열어 확인: https://pyeji.kr/og/default-YYYYMMDD.png (오늘 날짜)
- 페이스북 공유 디버거(https://developers.facebook.com/tools/debug/)도 og 태그 확인과 캐시 새로고침에 쓸 수 있다
