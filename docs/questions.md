## 작업 4. 메인 대시보드 구조 변경

결정한 것

  - 막차는 종료 시각이 정해진 경우만: `endsAt`이 있거나 다음 시즌이 발표된 경우(다음 시즌 시작이 곧 종료). 다음 시즌 미발표면 막차가 되지 않음

  - 메인, 게임 페이지 시즌 기록 표, 시즌 상세 상태, 폐지달력 막대 설명이 같은 단계를 씀

## 작업 12. 빌드 현황 "그 빌드, 지금은?" (구조와 화면만)

결정한 것
- 데이터: 마크다운 `src/content/builds/{게임id}/{slug}.md` 권장·채택. frontmatter에 구조화된 리그별 기록, 본문에 운영자 코멘트(자유롭게 쓰기 편함). JSON보다 평가 문장 쓰기·수정이 쉬움
  - name(통칭), nameEn, gameId, ascendancy{en, ko}, skills[{en, ko}], leagues[{seasonId, state, changes[{version, direction, patchUrl, note}], note}], updatedAt
  - state: buffed 강화 / nerfed 약화 / unchanged 큰 변화 없음 / dead 사실상 불가 / new 새로 등장
- 화면
  - 빌드 페이지 `/builds/{게임}/{slug}/`: 제목 "{통칭} 빌드 {최근 리그} 현황: 리그별 변화", 리그별 상태 띠(누르면 그 리그 설명으로 이동), 리그마다 변경 내용·공식 패치노트 링크, "운영자 평가" 칸
  - 리그별 한눈에 `/builds/{게임}/leagues/{리그}/`: 그 리그에서 상태가 바뀐 빌드 (큰 변화 없음 제외). 제목 "{약칭} {리그} 빌드 현황: 너프·버프된 빌드 한눈에"
  - 게임별 목록 `/builds/{게임}/`. 게임 페이지 머리에 "빌드 현황 N개", 시즌 상세 패치 칸 아래 "이 리그에서 바뀐 빌드 N개 보기" (빌드가 있을 때만)
  - 상태 색은 의미 색 토큰(--state-*)으로 따로, 다크 모드 값 포함. "인기 1위" 같은 순위 표현 없음
