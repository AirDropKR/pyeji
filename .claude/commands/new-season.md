새 시즌(리그·래더) 발표를 사이트 데이터에 반영한다. 입력: $ARGUMENTS

먼저 `docs/ops-common.md`의 공통 절차를 읽고 따른다 (CLAUDE.md 규칙 포함).

1. 입력의 링크가 모두 공식 출처인지 확인한다. 아니면 멈춘다.
2. 링크를 읽고 다음 값을 찾는다. 링크에 없는 값은 비워 두고 보고에 적는다.
   - 게임 (`src/data/games.json`의 id)
   - 시즌 이름: 국내 서비스사(카카오게임즈·블리자드 코리아)의 한국어 공식 이름. 한국어 공식 이름이 아직 없으면 영어 이름으로 넣고 questions.md에 "한국어 이름 확인 필요"
   - 영어 원제 `nameEn`
   - 시작 시각, 종료 시각(발표된 경우만). 시각 없이 날짜만이면 `timePrecision: "day"`
   - 발표가 확정인지(`confirmed`) 예상인지(`estimated`). 공식 날짜가 있으면 confirmed
3. `src/data/seasons.json`에서 같은 시즌을 찾는다 (게임 + 시즌 번호/버전).
   - 있으면: 바뀐 값만 고친다. `sourceUrl`은 더 최신 공식 공지면 교체하고, 이전 주소는 `note`에 남긴다
   - 없으면: 같은 게임의 기존 항목 모양 그대로 새 항목 추가. `id`는 `{게임}-{번호}`(예: poe1-3-31, d4-s16), `slug`는 기존 규칙(예: 3-31, season-16, ss15)
   - `highlights`는 공식 발표에 나온 사실을 직접 쓴 짧은 문장으로만, 없으면 넣지 않는다
4. 이 시즌에 연결된 글(`seasonId`가 같은 글)이 있으면, 바뀐 사실이 글 본문과 어긋나는지 확인하고 맨 아래 "## 업데이트" 맨 위에 `- {M}월 {D}일: {바뀐 내용 한 줄}`을 넣는다. 본문 고칠 곳이 크면 고치지 말고 `/update-post`를 쓰라고 보고한다.
5. 바뀐 것이 없으면 "바뀔 것 없음"으로 보고하고 끝낸다.
6. 공통 절차의 "끝낼 때"를 따른다. 커밋 예: `data: 3.30 시작 시각 반영 (/new-season)`
