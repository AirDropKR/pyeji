게임 발표(공개 방송, 신규 시즌 공개, 정식 출시 발표) 당일 사이트를 갱신한다. 입력: $ARGUMENTS

먼저 `docs/ops-common.md`의 공통 절차를 읽고 따른다 (CLAUDE.md 규칙 포함). 생중계 화면·채팅·기사는 근거가 아니다. 공식 공지 링크가 올라온 것만 반영한다.

시작 전: 링크가 모두 공식 출처인지 확인하고, 어느 게임·시즌·이벤트에 관한 발표인지 정한다. 이번 발표로 영향받는 것(`src/data/seasons.json`의 시즌, `events.json`의 이벤트, 그 시즌·이벤트에 연결된 글, 그 달 월간 글)을 목록으로 보여 주고 시작한다.

## 1순위: 이름·시각 (따로 커밋, 운영자가 바로 push)
1. 시즌 데이터: 한국어 공식 이름(없으면 영어로 먼저 넣고 questions.md에 "한국어 이름 확인 필요"), `nameEn`, 시작 시각(발표됐으면 `timePrecision: "exact"`), 종료 시각, `sourceUrl`, `highlights`(공개된 핵심 사실 3줄, 60자 이내 직접 쓴 문장)
2. 다음 시즌·이벤트 일정이 함께 발표됐으면 `/new-event`와 같은 방식으로 events.json
3. `npm run build` → 커밋 `data: {시즌} 이름·시작 시각 반영 (/event-day)` 하나로 끝내고, 보고에 "1순위 커밋 완료, push 가능"을 먼저 알린다. 운영자 push를 기다리지 않고 2순위로 넘어간다

## 2순위: 글
4. 그 시즌의 사전 정보 글: frontmatter `reveal`(발표 항목, `revealedAt`, `sourceUrls`) 추가, 첫 문단과 본문의 "아직 발표 전" 문장을 발표 내용으로, 제목에 시즌 이름, 맨 아래 업데이트 기록 한 줄 (`/update-post`와 같은 방식)
5. 발표 행사 자체를 다룬 글이 있으면 결과 정리로: 제목을 결과 중심으로, 지난 카운트다운(`countdownTo`) 삭제, 일정 표는 기록으로 남김
6. 그 달 월간 글의 해당 줄에 이름·시각
7. 빌드 → 커밋 `data: {시즌} 발표 내용 글 반영 (/event-day)`

## 3순위: 영상·키아트
8. 공식 공지에 들어 있는 유튜브 영상 ID → 시즌 `videos` (트레일러 먼저) → `npm run check:videos`로 공식 채널 확인
9. 공식 보도자료의 키아트 → `src/assets/seasons/{시즌 id}/key-art.jpg`(1600px JPG), `images` 첫 장. alt·캡션은 이미지를 직접 보고 쓴다. 출처 표기 필수. 보도자료에 없는 이미지는 쓰지 않는다
10. 빌드 → 커밋 `data: {시즌} 공식 영상·키아트 (/event-day)`

## 4순위: 알리기 준비 (파일만 만들고 실행은 운영자)
11. 색인 요청 목록을 보고에 넣는다: 바뀐 글 주소, 시즌 페이지, 게임 페이지, 메인, /now/. 서치 콘솔 "URL 검사 → 색인 생성 요청", 네이버 서치어드바이저 "웹 페이지 수집 요청"에 쓸 주소 그대로
12. 커뮤니티 공유용 짧은 글 초안 `drafts/community/{YYYY-MM-DD}-{시즌}.md`: 3~5줄, 발표된 사실(이름, 한국 시간 시작 시각)과 사이트 링크 하나. 과장·추측 없이, "폐지" 말장난은 한 번까지
13. 시작 시각이 오전 7시(매일 자동 재빌드) 이후라 메인·/now/ 반영이 늦어질 수 있으면, 보고에 "시작 직후 GitHub Actions → daily-rebuild 수동 실행"을 적는다

## 보고

- 바뀐 값: 이전 → 이후 (한국 시간)
- 반영하지 않은 것과 이유
