검색 실적을 보고 개선안을 만든다. 입력: $ARGUMENTS

먼저 `docs/ops-common.md`의 공통 절차를 읽고 따른다 (CLAUDE.md 규칙 포함).

1. 입력이 zip이면 PowerShell로 임시 폴더에 푼다: `Expand-Archive -Path {zip} -DestinationPath {임시 폴더}`. 파일이 없으면 멈춘다.
2. `node scripts/seo-candidates.mjs {폴더 또는 CSV}`로 순위 8~20위이면서 노출이 있는 검색어를 뽑는다.
3. 검색어마다 해당 페이지를 정한다.
   - CSV에 페이지 열이 있으면 그 페이지
   - 없으면(서치 콘솔 기본 내보내기는 검색어와 페이지가 따로) 사이트 글·시즌·게임 페이지 제목과 내용을 대조해 가장 맞는 페이지를 고르고 "추정"이라고 표시. 페이지 CSV(페이지.csv / Pages.csv)에서 그 페이지의 노출도 함께 본다
4. 페이지마다 개선안 (사실은 바꾸지 않고, 공식 출처에 있는 내용 안에서 표현만)
   - 제목: 그 검색어가 자연스럽게 들어가게. 날짜·시각이 답이면 제목에
   - 첫 문단: 검색어의 질문에 대한 답이 첫 문장에 오게
   - 소제목: 검색어가 묻는 것을 주제·질문형 소제목으로 (고정 소제목 금지)
   - 관련 페이지 간 내부 링크가 부족하면 어디에 무엇을 걸지
   - 애드센스 검토 중(docs/adsense-checklist.md 기준)이면 주소(slug) 변경은 제안하지 않는다. 검토가 끝난 뒤에도 주소 변경은 꼭 필요할 때만
5. 결과를 `docs/seo-weekly/{YYYY-MM-DD}.md`에 저장한다: 기간(내보내기 파일에 있으면), 후보 표(검색어 / 페이지 / 노출 / 클릭 / 순위), 페이지별 개선안(현재 → 제안), 맨 아래 "운영자 선택" 칸(번호만 적으면 되게)
6. 페이지는 고치지 않는다. 운영자가 번호를 고르면 그때 `/update-post` 방식으로 반영한다 (업데이트 기록 한 줄 포함).
7. 커밋 예: `docs: 10월 4주 검색 개선안 (/weekly-seo)`
